# Прогноз спроса на товарные позиции маркетплейса

## Описание проекта
Прогнозно-аналитическая система для оценки и прогнозирования спроса в электронной коммерции. Система реализует полный цикл работы с данными: от автоматизированного инкрементального сбора из разнородных источников до построения прогнозных моделей временных рядов и предоставления результатов на интерактивных дашбордах.

Проект разработан в рамках дисциплины **«Прогнозно-аналитические системы»** профиля подготовки **«Управление данными»**.

## Предметная область
Электронная коммерция (E-commerce). Анализ транзакций маркетплейса в разрезе категорий товаров и географии с учётом внешних экзогенных факторов (погода, сезонность) для оптимизации управления запасами.

## Прогнозируемый показатель
**Дневной спрос по товарным категориям (`category_name`):**
* Суммарная выручка (`total_sales`)
* Количество заказов (`order_count`)
* Средний чек (`avg_order_value`)

**Горизонт прогнозирования:** 7–14 дней.

## Источники данных (Разнородные)
1. **Транзакционные данные (CSV):** Исторический датасет продаж `Ecommerce_data.csv`. Содержит информацию о заказах (`order_id`), датах (`order_date`), клиентах, городах доставки (`customer_city`), категориях (`category_name`) и суммах (`sales_per_order`).
2. **Внешние факторы (Open-Meteo REST API):** Суточные метеорологические данные (температура, осадки, состояние погоды) по городам доставки. Загружаются автоматически через REST API в формате JSON без использования API-ключей. Интеграция выполняется по ключу `(order_date, customer_city)`.

## Архитектура данных и требования
* **Слои хранения (Medallion Architecture):**
  * `Bronze (Raw)` — необработанные CSV-файлы и JSON-ответы API.
  * `Silver (Cleaned)` — очищенные данные, приведённые типы, дедупликация и обработанные аномалии.
  * `Gold (Marts)` — агрегированная витрина с фичами (лаги, сезонность, погодные показатели) для ML-моделей.
* **Инкрементальность и идемпотентность:** Повторный запуск догружает только новые данные и не приводит к дублированию записей в витринах.
* **Контроль качества (Data Quality):** Автоматические проверки полноты, уникальности `order_id`, допустимости диапазонов цен/количества и ссылочной целостности. Некорректные данные отправляются в карантин (`quarantine`).
* **Мониторинг:** Фиксация результатов каждого запуска ETL-конвейера в таблице `load_logs`.

## Аналитический модуль
* **Модели прогнозирования:** Базовая (Prophet / SARIMAX) и градиентный бустинг (LightGBM / XGBoost) с валидацией через `TimeSeriesSplit`.
* **Дашборды:**
  * *Предметный:* Аналитика спроса, динамика продаж и прогноз на 14 дней.
  * *Операционный:* Мониторинг качества данных, статус ETL-запусков и свежесть витрин.
